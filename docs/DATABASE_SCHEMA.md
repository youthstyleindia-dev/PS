## 1. Identity, Governance & Authentication

### 1.1 `users`
Core user directory storing registered students, faculty, staff, proctors, drivers, and administrators.
- `id` (TEXT, PK): Canonical user UUID (e.g., `usr_student_1`).
- `name` (TEXT, NOT NULL): Full legal name.
- `email` (TEXT, UNIQUE, NOT NULL): Campus email address.
- `password_hash` (TEXT): Bcrypt salted password hash (cost factor 10).
- `avatar` (TEXT): DiceBear or campus avatar URI.
- `role` (TEXT, NOT NULL): Default primary role. `CHECK(role IN ('student', 'driver', 'proctor', 'ta_faculty', 'warden', 'admin', 'faculty'))`.
- `department` (TEXT): Academic or administrative department.
- `year_of_study` (INTEGER): 1 to 4 for students; NULL for staff/faculty.
- `bio` (TEXT): Profile summary.
- `is_active` (INTEGER, NOT NULL DEFAULT 1): Account status flag (0 or 1).
- `last_login` (TEXT): ISO 8601 timestamp of last authentication.
- `created_at`, `updated_at` (TEXT): Timestamps.

### 1.2 `role_assignments`
Enables fine-grained, multi-role assignments decoupled from single-role assumptions.
- `id` (TEXT, PK): Unique assignment identifier.
- `user_id` (TEXT, FK -> `users.id` ON DELETE CASCADE): Target user.
- `role_key` (TEXT, NOT NULL): Assigned role (`CHECK IN ('student', 'driver', 'proctor', 'ta_faculty', 'warden', 'admin')`).
- `status` (TEXT, NOT NULL DEFAULT 'active'): `CHECK IN ('active', 'revoked', 'expired')`.
- `granted_by_user_id` (TEXT, FK -> `users.id`): Administrator issuing the grant.
- `granted_at` (TEXT): Grant timestamp.
- `expires_at` (TEXT): Optional expiration.
- `revoked_at` (TEXT): Revocation timestamp if retracted.
- `reason` (TEXT): Administrative justification.
- *Constraint:* `UNIQUE(user_id, role_key) WHERE status = 'active'`.

### 1.3 `role_invitations`
One-time invitation links generated by administrators for onboarding specialized roles.
- `id` (TEXT, PK)
- `email_normalized` (TEXT, NOT NULL)
- `role_key` (TEXT, NOT NULL)
- `token_hash` (TEXT, NOT NULL): SHA-256 hash of secret token.
- `expires_at`, `used_at`, `created_by`, `created_at`, `revoked_at`

### 1.4 `password_reset_tokens`
Cryptographically random password reset tokens.
- `id` (TEXT, PK)
- `user_id` (TEXT, FK -> `users.id` ON DELETE CASCADE)
- `token_hash` (TEXT, NOT NULL)
- `expires_at`, `used_at`, `created_at`

### 1.5 `auth_sessions`
Active and revoked JWT session tracking for token invalidation and device management.
- `id` (TEXT, PK): Session UUID.
- `user_id` (TEXT, FK -> `users.id` ON DELETE CASCADE)
- `token_hash` (TEXT, NOT NULL): SHA-256 token digest.
- `user_agent` (TEXT), `ip_address` (TEXT)
- `expires_at` (TEXT, NOT NULL)
- `is_revoked` (INTEGER, NOT NULL DEFAULT 0)
- `created_at` (TEXT)

### 1.6 `auth_audit_log`
Immutable security ledger logging logins, role escalations, revocations, and failures.
- `id` (TEXT, PK)
- `user_id` (TEXT, FK -> `users.id` ON DELETE SET NULL)
- `email` (TEXT, NOT NULL)
- `event_type` (TEXT, NOT NULL)
- `ip_address`, `user_agent`, `metadata`, `created_at`

## 2. Module A: Student Intelligence & Academic Hub

### 2.1 `student_profiles`
Extended academic records, skills, and target career paths.
- `user_id` (TEXT, PK, FK -> `users.id` ON DELETE CASCADE)
- `skills` (TEXT, JSON array): Skills tagged with category and proficiency.
- `interests` (TEXT, JSON array)
- `target_role`, `target_company`, `placement_goals`
- `readiness_score` (INTEGER, CHECK 0..100)
- `resume_url`, `gpa`, `updated_at`

### 2.2 `placement_milestones`
Checklist items tracking individual student placement preparation.
- `id` (TEXT, PK)
- `student_id` (TEXT, FK -> `users.id` ON DELETE CASCADE)
- `title` (TEXT, NOT NULL)
- `category` (TEXT, CHECK IN ('DSA', 'SystemDesign', 'SoftSkills', 'Resume', 'MockInterview', 'Core CS', 'Projects', 'Fundamentals', 'FullStack'))
- `status` (TEXT, CHECK IN ('pending', 'in_progress', 'completed'))
- `target_date`, `completed_at`, `weight`, `created_at`

### 2.3 `mentors` & `mentorship_requests`
Senior peer and alumni mentorship registry and request lifecycle.
- `mentors`: `id`, `user_id` (UNIQUE), `company_offer`, `domain`, `skills`, `available_slots`, `max_mentees`, `active_mentees`, `rating`, `review_count`, `bio`.
- `mentorship_requests`: `id`, `mentee_id`, `mentor_id`, `topic`, `notes`, `preferred_slot`, `status` ('pending', 'accepted', 'rejected', 'completed'), `mentor_notes`.

### 2.4 `academic_resources`, `resource_ratings`, `resource_downloads`
Peer-shared syllabus notes, question banks, and cheat sheets with download counters and 5-star ratings.

## 3. Module B: Smart Campus Ride-Pooling

### 3.1 `campus_nodes` & `campus_edges`
Topological graph representing campus transit stations, road types, and congestion weights.
- `campus_nodes`: `id` (PK, e.g. `GATE_NORTH`), `name`, `zone`, `coord_x`, `coord_y`, `lat`, `lng`, `is_hub`.
- `campus_edges`: `id`, `source_node_id`, `target_node_id`, `distance_km`, `base_time_mins`, `road_type`, `speed_limit_kmh`, `current_congestion`, `is_bidirectional`.

### 3.2 `ride_offers` & `ride_requests`
Driver-published routes and student ride demand.
- `ride_offers`: `id`, `driver_id` (FK -> `users.id`), `origin_node_id`, `destination_node_id`, `departure_time`, `total_seats`, `available_seats`, `vehicle_type` ('EV_CAR', 'CAMPUS_SHUTTLE', 'PETROL_CAR', 'E_GOLF_CART'), `max_detour_ratio`, `status`, `planned_route`.
- `ride_requests`: `id`, `passenger_id` (FK -> `users.id`), `origin_node_id`, `destination_node_id`, `desired_departure_time`, `seats_needed`, `max_detour_ratio`, `status`.

### 3.3 `ride_matches` & `ride_bookings`
Computed graph pairings with Dijkstra shortest-path calculations.
- `ride_matches`: `id`, `offer_id`, `request_id`, `matched_path`, `driver_solo_distance_km`, `passenger_solo_distance_km`, `pooled_distance_km`, `shared_distance_km`, `detour_distance_km`, `detour_ratio`, `carbon_saved_kg`, `driver_earnings`, `passenger_fare`, `passenger_savings`, `status`.
- `ride_bookings`: `id`, `match_id`, `passenger_id`, `seats_booked`, `fare_paid`, `booked_at`.

## 4. Module C: Sustainable Computing Observatory

### 4.1 `service_workloads`
Microservice specifications tracking live replica counts and target RPS.
- `id` (PK), `service_name`, `service_type`, `baseline_replicas`, `current_replicas`, `target_rps`, `current_rps`, `is_eco_optimized`.

### 4.2 `telemetry_snapshots`
Simulated server telemetry recording CPU/GPU utilization, power consumption (Watts), PUE, and grid carbon emissions.
- `provenance`: `CHECK IN ('SIMULATED_WORKLOAD', 'ESTIMATED_METRIC', 'ACTUAL_MEASUREMENT')`.

### 4.3 `scenario_configurations`
What-If optimization toggles (dynamic frequency scaling, idle shutdown, solar shifting, query caching).

## 5. Module D: Privacy-Aware Digital Wellbeing

### 5.1 `focus_sessions` & `browsing_events`
Client-driven focus blocks and sanitized hostname telemetry.
- Strict Privacy: `browsing_events.sanitized_domain` contains hostname ONLY (e.g. `github.com`); URLs, queries, and path fragments are stripped before persistence.

### 5.2 `domain_rules`
Category mapping ('Productive', 'Distracting', 'Neutral') with global campus defaults and per-user overrides.

### 5.3 `cohort_aggregates`
Differential privacy aggregate table applying Laplace mechanism ($\varepsilon = 0.80$) and $k$-anonymity suppression ($k \ge 5$).

## 6. Module E: Responsible Examination Monitoring

### 6.1 `exam_sessions` & `exam_session_assignments`
Exam session parameters and proctor allocation.
- `exam_session_assignments`: Restricts proctors to observing and adjudicating only the sessions they are officially assigned to.

### 6.2 `observation_events`
Computer-vision and window event telemetry.
- `event_type`: `CHECK IN ('HEAD_POSE_DEVIATION', 'UNAUTHORIZED_PERSON', 'ABSENCE_FROM_SEAT', 'MULTIPLE_FACES', 'GAZE_AWAY', 'RESTRICTED_ZONE_INCURSION', 'MULTIPLE_OCCUPANTS_DETECTED', 'BROWSER_TAB_BLUR', 'FULLSCREEN_DEPARTURE')`.
- `review_status`: `CHECK IN ('PENDING_REVIEW', 'DISMISS_FALSE_POSITIVE', 'DISMISS_BENIGN_BEHAVIOR', 'ESCALATE_TO_INVIGILATOR')`.

### 6.3 `exam_audit_log`
Immutable, tamper-evident tribunal log requiring mandatory `reason_code` and `proctor_notes` for any status change.

## 7. Shared Notifications & Activity Feed

- **`activity_log`**: User actions logged per module (`hub`, `rides`, `sustainability`, `wellbeing`, `exams`, `system`).
- **`notifications`**: Targeted user alerts with read/unread tracking.
